### A.1 目录结构

反编译后无原始目录。根目录下有第三方库命名空间目录：

### A.6 效果结算主循环

`CombatManager.ApplyEffects`（`CombatManager.cs:1285-1372`）：

```csharp
public IEnumerator ApplyEffects(List<CardEffectState> effects, int selectedRoom, CardState playedCard = null, ... 16 个参数 ...)
{
    // 1. 先跑卡牌 traits 的 OnPreCardPlayed
    foreach (CardTraitState t in playedCard.GetTraitStates()) yield return t.OnPreCardPlayed(...);
    // 2. 组一个 CardEffectParams
    CardEffectParams p = new CardEffectParams { ...13 个 manager 引用... };
    // 3. 逐个效果执行
    for (int i = 0; i < effects.Count; i++) {
        p.finalEffectInSequence = (i == effects.Count - 1);
        yield return FireCardEffectInternal(effects[i], p, onPreEffectsFiredVfx, ...);
        if (p.targets.Count == 0) p.targets.AddRange(cachedTargets);   // ★ 目标在效果之间传递
        cachedTargets.Clear(); cachedTargets.AddRange(p.targets);
    }
    if (willFirePostEffects && onEffectsFired != null) yield return onEffectsFired(characterSummoned, allTargets);
}

private IEnumerator FireCardEffectInternal(CardEffectState s, CardEffectParams p, ...) {
    p.targets.Clear(); p.targetCards.Clear();
    if (GameEffectHelper.TestEffect(s, p, saveManager.PreviewMode)) {
        yield return GameEffectHelper.ApplyEffect(s, p, onPreEffectsFiredVfx, saveManager);
        effectsFiredAction?.Invoke();
    }
}
```

**关键点**：
- 效果之间通过 `p.targets` 传递「上一个效果打到了谁」→ 这是实现「造成伤害，然后对目标施加易伤」的机制，而不是每个效果自己重算目标。**要抄。**
- 整条链是 `IEnumerator`，因为要 `yield` 等动画。**不抄**（见 A.10 缺点）。
- 16 个默认参数的方法签名是典型的「不断加需求 → 加参数」的腐化结果。**不抄。**

### A.14 Monster Train 小结

**值得借鉴**
1. `XxxData`(SO) / `XxxState`(runtime) 命名与职责分离。
2. `CardEffectParams` 上下文对象：效果不依赖单例。
3. 效果基类只有 `Test` + `Apply` + `GetCardText` 三件事。
4. 效果之间通过 `targets` 传递目标。
5. 「先 Test 再 Apply」两阶段。
6. 触发用**队列**而非递归。
7. `Signal`（表现）与 `Trigger`（逻辑）分离。
8. `RngId` 多随机流。
9. X 费卡用 `CostType` 枚举而非特殊效果类。
10. 通用参数袋 + `useStatusEffectStackMultiplier` 这类开关，避免为「按层数缩放」再开新类。

**不建议照搬**
1. **333 个效果类**（74+43+162+54）。个人开发扛不住。
2. `Type.GetType(字符串)` 绑定效果类：无编译期检查、无法 Ctrl+点击跳转、重命名即崩。
3. 全链路 `IEnumerator`：逻辑无法脱离协程测试，无法快速模拟。
4. `ApplyEffects` 16 个参数。
5. `CombatManager` 3080 行 / `CardManager` 1913 行 / `CharacterState` 4123 行 / `SaveManager` 5019 行 —— 上帝类。
6. `IProvider` 隐式 DI：初始化顺序不可见。
7. `SaveManager` 出现在效果上下文里。
8. 字符串 ID（`"poison"`）满天飞。

### B.6 事件系统：IP_* 接口 + IReturn<T>（★ 全项目最优雅的设计）

55 个空标记接口：`IP_Act, IP_Awake, IP_BattleEnd, IP_BattleStart_Ones, IP_BuffAdd, IP_BuffSet, IP_DamageChange, IP_DamageTake, IP_DamageTakeChange, IP_Dead, IP_DeadAfter, IP_DealDamage, IP_DebuffResist, IP_Discard, IP_Dodge, IP_Draw, IP_Echo, IP_EnemyNewTurn, IP_FirstDrawBefore, IP_Getstat, IP_HPChange, IP_HealChange, IP_Healed, IP_Hit, IP_ItemGet, IP_ItemUse, IP_Kill, IP_NearDeath, IP_PlayerTurn, ...`

派发方式（`BattleSystem.cs:323-378`）：

```csharp
public List<T> IReturn<T>() where T : class {
    List<T> list = new List<T>();
    foreach (Item_Passive item in PlayData.Passive)        // 遗物
        if (item.ItemScript.OnePassive) list.Add(item.ItemScript as T);
    foreach (BattleChar c in Global)                        // 所有单位（含其身上的 Buff）
        foreach (T x in c.IReturn<T>()) list.Add(x);
    foreach (T x in AllyTeam.DummyCharAlly.IReturn<T>()) list.Add(x);
    foreach (Skill s in AllyTeam.Skills)                    // 牌库里所有卡的 Extended
        foreach (Skill_Extended e in s.AllExtendeds)
            if (e.OnePassive) list.Add(e as T);
    foreach (PassiveBase p in BattleExtended) list.Add(p as T);
    return list;
}
```

调用点（`BattleChar.cs:1633`）：
```csharp
foreach (IP_BuffAdd item in BattleSystem.instance.IReturn<IP_BuffAdd>()) { ... }
```

**为什么这个设计好**：
- **零订阅 / 零退订**。Buff 消失、卡被消耗、遗物被移除，监听器自动消失，不可能有悬挂监听。
- 想让某个 Buff 监听「受伤时」，只要 `class Buff_Thorns : Buff, IP_DamageTake`，不用在 `Init/OnDestroy` 里配对注册。
- 派发源是**显式列举**的，看一眼 `IReturn` 就知道谁可能被触发，比全局 `event` 好追踪得多。

**缺点**：每次派发都 `new List<T>()` + 大量 `as T`（含 null），战斗中高频调用会产生可观 GC。**我会保留思想、修掉 GC**（缓存 buffer + 不用 `as` 而用类型化列表）。

### B.9 Chrono Ark 小结

**值得借鉴**
1. **`IP_*` 标记接口 + `IReturn<T>` 拉取式派发** —— 无订阅、无泄漏、可追踪。（本架构的核心机制）
2. **`Skill_Extended` 组合式效果**：普通效果纯数据，特殊效果才写类。
3. **卡是普通 C# 对象**，`CloneSkill` / `TempSkill` 让造牌复制牌极其自然。
4. `Buff.StackInfo` 每层记录施加者与剩余时间。
5. `PassiveBase` 只有 5 个虚方法，钩子极少。
6. AI 基类只暴露 `SkillSelect` / `TargetSelect` 两个决策点。
7. `AgrroReturn` 权重轮盘赌 + 嘲讽优先。
8. 存档带 `GameVersion`。

**不建议照搬**
1. `BattleSystem.instance` 单例 + 3660 行 + 全 public 字段 + `List<object> BattleValues` 无类型黑板。
2. `Skill` 直接持有 `SkillButton MyButton`（UI）—— 逻辑依赖表现。
3. `AllyList => ...Cast<BattleAlly>().ToList()` 属性里做 LINQ 分配。
4. AI 里的 `BChar.Skills[3]` 魔数下标。
5. `Skill_Extended : Passive_Char : PassiveBase` 三层继承 + 职责混杂（既是卡效果又是被动）。
6. GDE 第三方数据方案 —— 现在应该直接用 ScriptableObject。
7. 逻辑与协程/动画深度缠绕（`ForceAction` 里同时做结算和播放）。
