# 第六部分：完整执行流程

每一步都写明「调用了哪个类的哪个方法」，AI 或人可以照着逐行核对。

---

## 1. 创建一张卡牌（编辑器操作，零代码）

1. `Assets/GameData/Cards/` 右键 → `Create → Game → Card` → 命名 `Card_Strike.asset`。
2. Inspector 填：`Id = "strike"`、`DisplayName = "打击"`、`Cost = 1`、`Type = Attack`、`TargetKind = SingleEnemy`。
3. `Effects` 列表点 `+`，从 `[SerializeReference]` 下拉里选 `DamageEffect`，填 `Amount.Base = 6`，`Target.Kind = ChosenTarget`。
4. `DescriptionTemplate` 填 `造成 {0} 点伤害。`
5. 选中 `GameDatabase.asset` → 右键 `从工程扫描全部资产`（`GameDatabase.ScanAll`）。

**不需要写任何 C#。** 只有当效果是全新机制（比如「消耗后回到手牌」）时，才在 `Effects/Impl/` 新增一个 30 行的类。

## 2. 将卡牌加入牌库

- 开局：`RunManager.StartNewRun()` → 遍历 `StarterDeckConfig` → `RunContext.AddCard(def)` → `new CardInstance(def)` 入 `RunContext.Deck`。
- 战斗奖励：`RewardScreen` → 玩家点选 → `RunContext.AddCard(def)`。
- 战斗中临时造牌：`AddCardEffect.Apply()` → `new CardInstance(def, temporary: true)` → `DeckController.AddCard(card, CardPile.Hand)`。
  临时卡 `IsTemporary = true`，`BattleController.TryPlayCard` 结算完会走 `Deck.Exhaust(card)`，**不会污染牌库**。

## 3. 开始战斗

```
RunManager.EnterNode(node)
  └─ node.Kind == Battle
      ├─ db.GetEncounter(node.EncounterId)
      ├─ SceneManager.LoadScene("Battle")  （或直接激活战斗根节点）
      └─ BattleController.StartBattle(run, encounter)
           ├─ new BattleContext { Rng = run.Rng, Run = run, Deck = new DeckController() }
           ├─ new BattleUnit("Player", run.MaxHp, true) { Hp = run.Hp }  → AllUnits
           ├─ foreach 敌人:
           │     hp = Rng.Range(RngStream.Encounter, MinHp, MaxHp+1)
           │     new BattleUnit(...) { EnemyDef = e, Brain = CreateBrain(e) }
           │     Brain.Init(unit, e)
           │     unit.AddStatus(...) 起始状态
           ├─ Deck.Init(ctx, run.Deck)        ← 固有牌置顶，其余 Rng.Shuffle(CardDraw)
           ├─ Post(BattleStarted)
           ├─ Collect<IBattleFlowHook>() → OnBattleStart   ← 遗物「开局获得 X」在这里生效
           ├─ RunTriggerQueue()
           └─ BeginTurn()
```

`BattlePresenter.Awake` 拿到 `BattleController.Ctx`，之后每帧从 `Ctx.Events` 出队播放。

## 4. 抽牌

```
BattleController.BeginTurn()
  └─ Deck.Draw(run.CardsPerTurn)
       └─ for n 次 DrawOne():
            ├─ Hand.Count >= MaxHandSize ? return false
            ├─ DrawPile 空 → ReshuffleDiscardIntoDraw()
            │     ├─ DrawPile.AddRange(DiscardPile); DiscardPile.Clear()
            │     ├─ Rng.Shuffle(RngStream.CardDraw, DrawPile)
            │     └─ Post(DeckShuffled)
            ├─ 取 DrawPile 末尾 → Hand
            ├─ Post(CardDrawn)
            └─ Collect<ICardPlayHook>() → OnCardDrawn   ← 「抽到时」类效果在这里
```

`BattlePresenter` 收到 `CardDrawn` → `HandView.SpawnCard(uid)` → DOTween 从牌堆位置飞入 → `HandView.Rearrange()`。

## 5. 玩家选择卡牌

纯 UI 行为，逻辑层不参与：

```
CardView.OnBeginDrag
  └─ TargetingController.Begin(card)
       ├─ card.Def.TargetKind == SingleEnemy → 画指向箭头，高亮所有存活敌人
       ├─ card.Def.TargetKind == None/Self/AllEnemies → 拖到「出牌区」即可
       └─ 实时调用 BattleController.CanPlayCard(card, hoveredUnit, out reason) 做变灰/提示
```

**注意**：`CanPlayCard` 是纯查询，无副作用，UI 可以每帧调。它内部会 `PrepareContext` 并调 `EffectResolver.CanApplyAll`——所以「手牌满时抽牌卡不可打」这类规则自动生效。

## 6. 验证费用和目标

```
BattleController.CanPlayCard(card, target, out reason)
  ├─ Phase != PlayerTurn                → NotPlayerTurn
  ├─ !Hand.Contains(card)               → NotInHand
  ├─ Unplayable 关键字 / CostMode        → Unplayable
  ├─ cost = card.GetCost(Ctx)
  │     └─ Def.Cost + BattleCostDelta + TurnCostDelta
  │        + Collect<ICardPlayHook>().ModifyCardCost(...)   ← 遗物/状态减费
  ├─ cost > Ctx.Energy                  → NotEnoughEnergy
  ├─ TargetKind==SingleEnemy 且 target 非法 → NeedTarget / InvalidTarget
  └─ EffectResolver.CanApplyAll(effects, ctx) → EffectCannotApply
```

## 7. 播放卡牌

```
BattleController.TryPlayCard(card, target, out reason)
  ├─ CanPlayCard(...) 复查（防 UI 状态过期）
  ├─ spend = CostMode==X ? Ctx.Energy : cost
  ├─ Ctx.SpendEnergy(spend) → Post(EnergyChanged)
  ├─ PrepareContext(card, target, cost)  → _playCtx.XValue = spend
  ├─ Hand.Remove(card)        ★ 先离手，防止「弃掉所有手牌」把自己也算进去
  ├─ Ctx.CardsPlayedThisTurn++ ; Ctx.LastCardTypePlayed = card.Type
  ├─ Post(CardPlayed)
  ├─ Collect<ICardPlayHook>() → OnCardPlayed    ← 「每打出一张攻击牌…」在这里
  ├─ EffectResolver.ResolveAll(card.Def.Effects, _playCtx)   ← 见第 8 步
  ├─ Ctx.RunTriggerQueue()
  ├─ 归宿：Power → 消失 / Exhaust 关键字或临时卡 → Exhaust / 其余 → Discard
  └─ CheckBattleEnd()
```

## 8. 执行多个效果

```
EffectResolver.ResolveAll(effects, ctx)
  └─ for i in effects:
       Resolve(effects[i], ctx)
         ├─ ctx.Depth > MaxDepth(8) → 警告并中断     ★ 防无限递归
         ├─ TargetResolver.Resolve(effect.Target, ctx, ctx.Targets)
         │     └─ Kind==PreviousTargets 时读 ctx.LastTargets   ★ 目标在效果间传递
         ├─ effect.CanApply(ctx) 为 false → 跳过（不报错，用于条件效果）
         ├─ effect.Apply(ctx)
         ├─ ctx.CarryTargetsForward()    ← Targets 非空才覆盖 LastTargets
         └─ ctx.Battle.RunTriggerQueue() ← 消费本效果引发的连锁（死亡、荆棘等）
```

举例 —— `Bash`（造成 8 点伤害并施加 2 层易伤）：

```
Effects[0] = DamageEffect  { Target=ChosenTarget, Amount=8 }
Effects[1] = ApplyStatusEffect { Target=PreviousTargets, Status=vulnerable, Stacks=2 }
```

第二个效果不需要重新选目标，直接命中第一个效果打到的人。**这正是从 Monster Train `CombatManager.ApplyEffects` 学来的机制。**

## 9. 触发状态效果

伤害管线（`BattleUnit.TakeDamage`）里 Hook 的调用顺序：

```
DamageInfo { Amount = 8, Kind = Attack, Attacker = 玩家, Card = Bash }
  │
  ├─ hooks = ctx.Collect<IDamageHook>()      ← 现场收集，按 Order 排序
  │     来源 = 所有存活单位身上所有状态的所有 Behaviour + 遗物
  │
  ├─ 【攻方】Owner == Attacker 的 ModifyOutgoingDamage
  │     StrengthBehaviour(Order=AddFlat)   → Amount += stacks
  │     WeakBehaviour(Order=Multiply)      → Amount = Amount * 75 / 100
  │
  ├─ 【受方】Owner == this 的 ModifyIncomingDamage
  │     VulnerableBehaviour(Order=Multiply)→ Amount = Amount * 150 / 100
  │
  ├─ 护甲抵扣 → Post(DamageBlocked)
  ├─ 扣血     → Post(DamageDealt)
  ├─ 【受方】OnDamaged                     ← 荆棘反伤在这里，通过 EnqueueTrigger 排队
  └─ Hp<=0 → ctx.EnqueueTrigger(() => Die(ctx))   ★ 死亡不在管线内递归
```

回合结束的状态触发（中毒）：

```
BattleController.EndTurn()
  └─ Collect<ITurnHook>() → OnTurnEnd
       └─ PoisonBehaviour.OnTurnEnd(ctx, src)
            └─ src.Owner.TakeDamage(ctx, new DamageInfo { Amount = src.Stacks, Kind = Status, IgnoreBlock = true })
  └─ RunTriggerQueue()
  └─ TickStatusDecay(atTurnStart:false)   ← Decay=LoseOneAtTurnEnd 的状态在这里 -1
```

**为什么衰减放在 Hook 之后**：中毒必须先造成 N 点伤害，再降 1 层。顺序写反是最常见的 bug。

## 10. 更新 UI

逻辑层跑完时，`Ctx.Events` 里已经排好了一串事件。`BattlePresenter` 每帧消费：

```csharp
void Update()
{
    if (_playing) return;                       // 上一条动画还没播完
    if (_ctx.Events.Count == 0) { RefreshStatic(); return; }
    var e = _ctx.Events.Dequeue();
    _playing = true;
    PlayEvent(e, () => _playing = false);       // 内部用 DOTween/协程
}

void PlayEvent(in BattleEvent e, System.Action done)
{
    switch (e.Type)
    {
        case BattleEventType.DamageDealt:
            var view = _views[e.TargetUid];
            view.PlayHit();
            DamagePopup.Spawn(view.transform.position, e.Value);
            Sfx.Play("hit");
            DOVirtual.DelayedCall(0.15f, () => done()); break;
        case BattleEventType.CardDrawn:
            _hand.SpawnAndFlyIn(e.TargetUid, done); break;
        ...
        default: done(); break;
    }
}
```

**关键性质**：即使 `BattlePresenter` 整个不存在（比如单元测试里），战斗依然能跑完，只是事件堆在队列里没人消费。这就是「可无 UI 运行」。

血条、能量、状态图标这类**当前值**不走事件，`RefreshStatic()` 直接读 `BattleUnit.Hp` 等字段。事件只负责**动画和瞬时反馈**。

## 11. 卡牌进入弃牌堆或消耗牌堆

见第 7 步末尾。三条规则：

| 情况 | 归宿 | 代码位置 |
|---|---|---|
| `Type == Power` | 消失（不进任何堆） | `TryPlayCard` |
| 有 `Exhaust` 关键字，或 `IsTemporary` | `ExhaustPile` | `Deck.Exhaust` |
| 其他 | `DiscardPile` | `Deck.Discard(card, fromHand:false)` |

回合结束时手牌处理（`DeckController.EndTurnDiscard`）：`Ethereal` → 消耗；`Retain` → 留手；其余 → 弃牌。同时 `card.OnTurnEnd()` 清掉 `TurnCostDelta`。

## 12. 敌人执行行动

```
BattleController.EndTurn() → EnemyTurn()
  └─ foreach 存活敌人 u:
       ├─ u.DecayBlock(ctx)
       ├─ u.Brain.ExecuteIntent(ctx)
       │    ├─ action = Def.Actions[u.CurrentIntent.ActionIndex]
       │    ├─ effCtx = new EffectContext { Battle=ctx, Source=u, ChosenTarget=ctx.Player }
       │    └─ EffectResolver.ResolveAll(action.Effects, effCtx)   ★ 敌人和卡牌走同一套效果系统
       ├─ ctx.RunTriggerQueue()
       └─ CheckBattleEnd()
  └─ TickStatusDecay(atTurnStart:false)
  └─ BeginTurn()
```

下一回合的意图在 `BeginTurn()` 里决定：

```
foreach 敌人: u.Brain.DecideIntent(ctx)
  ├─ UpdatePhase(ctx)        ← 多阶段 Boss 检查血量阈值
  ├─ idx = ChooseAction(ctx) ← 固定序列 / 权重随机 / 条件 / 连续限制
  ├─ History.Add(idx)
  ├─ Unit.CurrentIntent = BuildIntent(...)   ← 预览伤害值（含力量加成）
  └─ Post(IntentChanged)
```

**意图值必须是「预览」而非「实际」**：`DamageEffect.PreviewDamage` 会跑一遍攻方 Hook 修正但不真的造成伤害，这样 UI 上显示的 12 就是玩家实际会挨的 12。

## 13. 战斗结束

```
CheckBattleEnd()
  ├─ !Player.IsAlive      → EndBattle(false)
  └─ AliveEnemyCount == 0 → EndBattle(true)

EndBattle(victory)
  ├─ Ctx.BattleEnded = true ; Phase = Victory/Defeat
  ├─ Collect<IBattleFlowHook>() → OnBattleEnd(victory)
  ├─ foreach card in Run.Deck: card.OnBattleEnd()   ← 清临时费用/临时关键字
  ├─ Run.Hp = Player.Hp                             ← ★ 血量写回 RunContext
  └─ Post(BattleEnded)
```

`BattlePresenter` 播完 `BattleEnded` 事件后通知 `RunManager.OnBattleEnd(victory)`：

```
RunManager.OnBattleEnd(true)
  ├─ Run.Gold += Rng.Range(RngStream.Reward, 10, 21)
  ├─ 生成 3 张候选卡：Rng.Pick(RngStream.Reward, cardPool)（去重、按稀有度权重）
  ├─ Phase = RunPhase.Reward → RewardScreen.Show(rewards)
  └─ 玩家选完 → RunContext.AddCard(def) → SaveSystem.SaveRun(run) → ReturnToMap()
```

## 14. 保存当前游戏进度

**存档时机**：只在**安全点**存，绝不在战斗中途存。

| 时机 | 调用 |
|---|---|
| 进入地图界面 | `SaveSystem.SaveRun(run)` |
| 领完奖励 | `SaveSystem.SaveRun(run)` |
| 商店购买后 | `SaveSystem.SaveRun(run)` |
| 事件结束后 | `SaveSystem.SaveRun(run)` |
| 一局结束 | `SaveSystem.DeleteRun()` + `SaveSystem.SaveMeta(meta)` |

**为什么不存战斗中途**：战斗状态（手牌、牌堆顺序、敌人意图、所有状态层数）序列化量大且极易出 bug；而 Roguelike 玩家的实际需求是「关掉游戏明天接着打」，节点级存档已经足够。
**如果将来必须支持战斗中存档**：`BattleContext` 已经是纯数据 + `Rng` 可存取，只需再写一个 `BattleSave` DTO，不需要改架构。这是本设计留的口子。

存档内容：

```
run.json  { Version, Seed, RngStates[], Hp, MaxHp, Gold, FloorIndex, CurrentNodeId,
            Cards[{DefId, UpgradeLevel}], RelicIds[], Map[] }
meta.json { Version, UnlockedCardIds[], UnlockedRelicIds[], BestFloor, 音量/语言 }
```

**卡牌只存 `DefId + UpgradeLevel`**，读档时 `db.GetCard(id)` 重建。找不到的卡打 Warning 跳过而不是崩溃——这样删除一张卡的资产不会让老存档全废。

**随机种子**：`RngStates` 存的是每条流的当前状态而非只存初始种子。这样读档后抽牌序列、奖励序列都与关闭前完全一致，玩家无法通过 SL 刷奖励。
